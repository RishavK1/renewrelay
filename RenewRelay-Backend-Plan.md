## 2. Repository and coding standards

| Directory | Responsibilities |
|---|---|
| `apps/web` | Next.js UI, server-rendered read adapters, versioned routes, auth wiring, public decision and webhook entry points. Map transport input and errors here. |
| `apps/worker` | Job polling, leasing, scheduling, dispatch, webhook processing and reconciliation. Invoke the same commands as the web app. |
| `packages/domain` | Feature modules for workspaces, clients, renewals, decisions, imports, notifications and billing. Own policies, state transitions, recurrence and service contracts. Domain logic depends on typed ports for persistence, the clock and external services. |
| `packages/db` | Prisma schema, migrations, tenant transaction, concrete repositories, lease and maintenance queries. Each feature owns its repository queries. |
| `packages/contracts` | Zod schemas, request and response DTOs, error codes and versioned route definitions. Separate staff, public and webhook payloads. |
| `packages/integrations` | Resend and Razorpay clients, signature verification, provider event mapping and test fakes. |
| `tests`, `infra`, `docs` | Cross-module acceptance tests and fixtures, deployment definitions, contracts, architecture decisions and runbooks. Co-locate pure domain tests. |

- Keep handlers thin. The common command path validates input, resolves the actor and tenant, checks permissions and entitlement, runs the locked transaction, records the outcome and maps a typed result. Server-rendered reads call the same authorized query functions without an internal HTTP round trip.
- Reuse tenant context, authorization policy, clock/date math, idempotency, audit and notification logic. Keep side effects behind adapters, with explicit timeouts and retry rules. External network calls run outside database transactions.
- Use strict types, explicit DTO field allowlists, bounded inputs, predictable errors, named domain operations and reviewed migrations. Keep shared modules small and cohesive. Check forbidden dependency directions and unsafe SQL in CI.
- Use a generated OpenAPI inventory from the adopted contracts or a checked-in equivalent with drift checks. Document permission, retry, version and error behavior for every command.

## 3. Storage and transactional invariants

| Data | Rules enforced by schema and commands |
|---|---|
| Workspaces, memberships, invites | Keep global auth identity separate from tenant roles. Unique membership per user/workspace. A partial unique index enforces at most one active owner. Workspace creation and transfer enforce exactly one in the same transaction. Bind single-use invitation digests to the normalized verified invited address. Reject expired, revoked, reused and mismatched invitations. |
| Clients, contacts, items | All tenant relationships use composite workspace foreign keys. A request's contact must also belong to the item's client. Assignees reference workspace memberships. Archive retains historical records. Draft status controls activation and sends. |
| Cycles | Unique item and sequence, plus one open cycle per item. Store the cycle timezone and recurrence anchor independently of the mutable item template. Status, next action, quoted amount and supplier cost, payer and rebillable context, billing flag, actual provider action and closure data are explicit. Keep searchable next-action data consistent with the state transition. |
| Decision requests, credentials, responses | Store immutable terms and recipient snapshots per revision, including issuer, note and term. Separate digested link credentials, scoped sessions and OTP challenges. Allow many question messages and one final response per revision. History retains attribution, superseded decisions and corrections. |
| Audit and idempotency | Append-only audit for runtime roles. Store actor kind and identity, change summary, entity, timestamp and correlation ID. Minimize sensitive fields. Scope idempotency by workspace, command and actor or public request scope. Bind to a canonical request hash, store the committed result and define a retention period for safe retries. Recheck present access before returning a replay. |
| Outbox, deliveries and provider inbox | Unique job/send key, lease token, lease expiry, attempt count, first-send time, status and provider correlation. Separate application job outcome from provider delivery. Global inbox is deliberately isolated. Map verified provider events to a workspace through preexisting provider-account and resource mappings. |
| Imports and exports | Store staged, normalized rows and a digest with a 24-hour preview expiry. Preserve minimal committed batch fingerprint and result for the agreed replay period without retaining the upload. Stream and bound exports with tenant filters and audit records. |
| Subscriptions, entitlements and deletion | Keep provider resource IDs, internal plan, paid-through, grace and effective entitlement separate. Record administrative pilot grants with actor, evidence, reason and expiry. Track deletion requested, recoverable and purged states independently of provider subscription state. |

Use database `DATE` for calendar dates, UTC event timestamps, bounded integer minor units and a supported ISO currency allowlist with correct currency exponents. Unknown monetary values use null. Validate intentional zero separately from unknown, group totals by currency and define a lossless API range for integers.

Apply RLS with fail-closed policies (including write checks), FORCE RLS where appropriate and runtime roles without ownership, unrestricted maintenance permissions or RLS bypass. Set the tenant context locally inside every database transaction. Keep explicit tenant predicates and verify that context clears when the transaction ends or aborts. Resolve initial membership or public credential scope through narrowly granted lookup paths. Lease due cross-tenant jobs via a restricted dispatch path that returns minimal identifiers. Process each job through its own tenant transaction. [PostgreSQL row security](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)

Acquire locks in a documented order. For quota or entitlement mutations, lock the workspace first. For lifecycle actions, lock the cycle before its request or credential rows. Serialize membership removal with assignments and commands that depend on active membership. Recheck active membership, entitlement, expected version and current revision in the transaction as applicable. Commit the business change, idempotency result, audit and outbox together. Bound lock and transaction timeouts and retry selected database conflicts within a budget. Use production-shaped indexes for the work queue, memberships, audit history and due jobs. The queue cursor must encode the full selected sort order, including overdue sort rank, next-action date and ID, with a fixed local-date cutoff for that page sequence.

## 4. Workflow, permissions and API

| Stage | Contract and edge cases |
|---|---|
| Workspace and clients | Owner alone manages subscription, ownership and deletion. Owner/admin manage invites, membership and whole-workspace import/export. Members manage clients and renewals across their workspace. A client contact sees only the scoped decision. Support has no standing access. Removal revokes access to that workspace immediately and reassigns open work and draft items atomically to an active member. |
| Register and queue | Service expiry, provider notice and client reply deadlines have distinct meanings. Reply is due on or before the earliest applicable action deadline. Queue includes waiting on client, ready for operator, due within 30 local days, overdue and delivery failed. Preserve blockers such as missed provider notice or provider rejection until explicitly resolved. Overdue and delivery failures are flags and can overlap the primary state. |
| Request and response | Save the canonical snapshot before queueing the invitation. Client chooses approve, request cancellation or ask a question. A question leaves the cycle awaiting decision and notifies the operator. The operator records resolution and can revise terms. A final decision produces an operator task, stops reminders and invalidates every credential for the revision. Keep approval evidence and its audit attribution. Offline decisions use the same lifecycle rules with source, date, reason and recording staff member. |
| Revisions and resends | Changes to price, term, recipient or deadline supersede the revision and any applicable approval before execution. Reissue the current snapshot with new credentials on a manual resend. A stale browser receives a neutral conflict/status response, and sensitive receipt information requires fresh scoped authorization. |
| Provider completion | Record the actual renewal or cancellation date and provider reference or explanatory note. An auto-renew outcome requires confirmation. Close and insert any confirmed recurring successor in the same commit. A one-off renewal or completed cancellation creates no successor. Missing response, delivery failure and expiry preserve open work and never imply consent. |
| Correction and archive | Withdrawal requires a reason. Corrections append to closed history and any change to a successor requires explicit confirmation. Archive requires resolution or explicit abandonment and reason, invalidates public access and cancels pending sends. Archived history stays exportable. |
| Billing flag | Agency-paid rebillable completion defaults to `to invoice`. Store `not applicable`, `to invoice` or `invoiced` and an invoice reference as appropriate. The queue exposes renewals still to invoice independently of provider completion. |

**API inventory**

| Surface | Endpoints and contract |
|---|---|
| Workspace | `POST /api/v1/workspaces`. Under `/api/v1/workspaces/{wid}`, create invites, remove members with a replacement, transfer ownership and request deletion. Invite acceptance resolves the workspace from the invite. Use an explicit POST and verified staff identity. |
| Clients and items | Scoped list/create/edit/archive for clients and items, plus scoped contact creation and editing. Creating an item creates its first cycle. Address changes on contacts must invalidate affected pending credentials through the same revision policy. |
| Cycles | Scoped list/detail and commands for ready, request, revise, resend, record-offline, complete, withdraw, correct, billing and archive/abandon where applicable. Lists support client, provider, assignee, date, state and billing filters with limit 100 and opaque validated cursors. |
| Public decisions | `GET /d/{token}` exchanges the credential for a short scoped preview session and redirects to a clean URL. Public API POSTs start OTP, verify OTP, reissue and submit the confirmed response. GET creates no decision and does not consume the link or trigger a message. |
| Imports and export | Scoped template download, preview and atomic commit. CSV export uses approved filters and role checks on the request. |
| Subscription and integrations | Scoped owner-only checkout, cancel and status. Signed raw-body endpoints at `/api/v1/webhooks/mail` and `/api/v1/webhooks/billing`. |

Commands take an `Idempotency-Key` and versioned mutations take `expectedVersion`. An authorized exact replay returns the prior result. A changed payload with the same key or a stale version returns 409. Response errors have code, safe message, field errors where applicable and request ID. Use 400 for invalid input shape, 401 for absent session, 403 for a visible role or entitlement denial, 404 for inaccessible tenant resources, 409 for conflicts and quota, 410 for expired public credentials where safe, 422 for invalid transitions, and 429 with bounded retry guidance. Public response payloads use the stored terms and identity from the request revision. Client-supplied prices, workspace roles or operator IDs cannot grant access or replace approved terms.

The hosting acceptance fixture uses a 30 June expiry and 15 June response deadline. Item and cycle creation capture the payer, operator, ₹8,000 supplier cost and ₹10,000 quote. The request command publishes only the quote, term and public deadline. A verified response puts the cycle in the operator's queue. The completion command records the provider reference, closes the cycle with `to invoice` for an agency-paid rebillable item and creates one confirmed successor. The billing update records the invoice reference on the completed cycle. Audit history links each action to its actor and the approved revision.

## 6. Scheduling, imports, billing and recovery

### Notifications and dates

- Compute due windows using the cycle's IANA timezone. A due date is inclusive through that local date. Monthly recurrence retains its original anchor through short months. Annual February 29 clamps and returns to February 29 in leap years. Test DST, leap years, timezone changes and workspace-date boundaries with a fixed clock. Preview timezone changes and explicitly reschedule affected open cycles.
- Before the decision, the reply deadline drives the next action, subject to provider deadlines. After the decision, the earliest applicable provider action deadline drives the operator queue. Preserve a missed notice as an explicit blocker. Schedule internal reminders at 09:00 local, 30, 7 and 1 day before the earliest actionable deadline. Schedule client reminders 7 and 1 day before the requested response after the initial invitation. Deduplicate offsets, skip elapsed scheduled reminders and send a daily actionable overdue digest. Overdue imports send one owner notification only after explicit activation. Bounces or complaints suppress the address and create an internal exception.
- Poll every 30 seconds. Start with leases of 25 jobs for two minutes and extend leases for legitimate long work. Fence worker finalization with the lease token. Recheck active cycle, current revision, entitlement and suppression immediately before send. Freeze provider payload across retries with one stable send key. Retry transient failures with jitter around 1, 5, 30 and 120 minutes. Resend documents a 24-hour deduplication window, so route ambiguous sends outside that window to reconciliation. An email already accepted by a provider can still arrive after a revision or suspension. Revocation and entitlement checks protect subsequent access. [Resend idempotency](https://resend.com/docs/dashboard/emails/idempotency-keys)
- Replays and dead-letter recovery must recheck business eligibility. Resubmission after a definite failure should preserve the intended recipient and record the audit trail. A transport receipt records delivery state only.

### Imports and entitlement

- Preview returns row errors, possible duplicates and overdue choices. Commit rechecks membership, preview version and expiry, duplicates and quota under the workspace lock. Commit validated rows, audit and job records atomically. An exact committed replay returns the original summary. Similar names across clients remain independent.
- Use one entitlement policy for web commands, public decisions and worker sends. Trial proposal is 14 days, 10 items, 3 seats. Paid proposal is ₹1,499/month, 100 items and 5 seats including owner. Pending invites reserve seats. Closing a cycle must remain possible at quota. Trial expiry and paid suspension enter read/export mode and stop outbound workflow messages and public actions. Trial expiry gets a warning three days prior. Payment failure preserves paid-through coverage, then seven days of grace. Scheduled cancellation runs to paid-through. Reactivation schedules future work and may offer one catch-up digest.
- Checkout redirects display processing. Use verified provider status and confirmed paid periods to grant access. Persist and process webhooks idempotently, fetch authoritative state on conflicts, and reconcile daily. Protect checkout creation with a durable intent and recovery for a lost provider response to avoid duplicate subscriptions. Track cancellations and refunds explicitly and verify settlement independently. Support approved paid-pilot grants only with recorded evidence and expiry.
- On deletion, require recent owner authentication, confirm export and scope, stop sends, revoke credentials and resolve the platform subscription. Propose a 30-day recovery window before purge. Review billing record retention with accounting and define how deletion and revocation records are recovered after a database restore.

### Operations

Track queue read latency, due-job age, retries, dead letters, mail bounces, decision errors, webhook backlog, db connection saturation and backup health. Alert after two checks with oldest due job over five minutes, billing events pending over 15 minutes, or backup failure. Record provider outages separately. Use structured logs with correlation IDs and access-controlled retention.

Test the spec's proposed targets at 100 workspaces × 100 items. Measure p95 queue reads under 500 ms and 99% of reminders handed to the provider within five minutes while healthy. Verify queue behavior under overlap with imports and webhooks. Enable point-in-time recovery, rehearse weekly in pilot and measure up to 15 minutes of data loss and up to four hours of recovery. Restore into an isolated instance with sends and billing operations disabled. Reconcile provider messages and payments, recover revocations and deletions, invalidate uncertain credentials, then enable side effects. Independently exercise mail and billing kill switches. [Amazon RDS point-in-time restore](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/USER_PIT.html)

Promote one immutable image through staging and production. Run migrations as a separate step with separate credentials. CI runs lint and type checks, fresh and previous-schema migrations, pure workflow tests, real Postgres integration and staff-to-client Playwright tests. Use expand/backfill/switch/contract releases for breaking changes. Rehearse compatible rollback. Keep external sends and billing gated independently until their releases pass.
